# セキュア API レビュー

API エンドポイントを作成・変更するときは、以下を適用すること。

1. 認証: すべてのエンドポイントにゲートウェイ JWT を要求する。/health 以外に匿名で叩けるルートを作らない。
2. 入力検証: 規定の形式に合わない claim id は、claims-core へ到達する前に拒否する。
3. 監査: 状態を変更するエンドポイントは、実行者・操作・対象・時刻を含む監査イベントを発行する。読み取り専用のエンドポイントは発行しないが、その場合は黙って省略せず「読み取り専用のため発行しない」と要約に明記すること。
4. データ分類: レスポンスは許可リストから組み立てる。上流のレコードをそのまま返さない。許可リストにないフィールドがレスポンスやログに出ないようにする。
5. 列挙対策: 呼び出し元が所有していないリソースへのリクエストは、存在しないリソースへのリクエストと区別がつかないようにする。

`scripts/check-endpoints.sh` を実行し、その出力を要約に含めること。
