# Intent: エージェント設定の回帰テスト

- 起案者: リポジトリ作者
- ステータス: accepted
- 日付: 2026-09-13
- 作成方法: Claude Code のセッションで起草し、スコープを人が絞り込んだ

## 問題

`claims_api/` の変更は `tests/` が守っている。エージェントを制御する設定そのものは、誰も守っていない。

`CLAUDE.md`、`.claude/**`、`scripts/**` は、セッションの挙動を決めるという意味でコードと同じ働きをする。ところがこれらを壊す差分は、既存の検証を一つも落とさない。

- `.claude/agents/verifier.md` の `tools` に `Edit` を足しても、`make test` は 11 passed のまま通る。spec R5 の要件が消えたことに誰も気づかない。
- `.claude/hooks/protect-paths.sh` の `case` 文からパターンを1つ消しても同じ。凍結パスが開いたことは、誰かが実際に `claims_api/legacy_v1/` を編集しようとするまで分からない。
- `scripts/check-endpoints.sh` の条項4の `grep` を消しても同じ。バックストップが空振りするようになったことが見えない。

制御は置いた時点が最も強く、あとは劣化する。劣化に気づく手段が無いことが問題である。

## 期待する成果

`CLAUDE.md`、`.claude/**`、`scripts/**` に差分が出たとき、決定的な制御が今も効いていることを機械的に確認できる。

確認は CI で走り、人が思い出すかどうかに依存しない。制御を弱める差分は、レビュアーの注意力ではなく赤いビルドで止まる。

## 影響を受ける利用者とシステム

このリポジトリを触る人、Claude Code のセッション、CI。

## 制約

- 新しい実行時依存を増やさないこと。`CLAUDE.md` の「標準ライブラリと Flask のみ」を曲げない。
- eval は決定的であること。CI から外部サービスやモデル API を呼ばない。呼べば、制御の劣化ではなくネットワークとモデルの揺らぎを測ることになる。
- 助言的な制御と決定的な制御を混同しないこと。`intent/review-pass.md` から引き継ぐ。eval で測れるのは決定的な側だけであり、測れていない側があることを成果物に書く。

## 未解決の問い

- 助言的な制御（skill、`CLAUDE.md`、`REVIEW.md`）が実際にセッションの出力を変えるかは、モデルを呼ばないと測れない。それを eval と呼べるようにするには API キーと依存が要る。この範囲に踏み込むかは決めていない。
- 既知の穴（塞いでいないと分かっている箇所）を eval でどう表現するか。通る eval にすると穴が仕様に見え、書かないと穴が見えなくなる。
