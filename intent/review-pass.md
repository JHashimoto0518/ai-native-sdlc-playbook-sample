# Intent: レビューパス

- 起案者: リポジトリ作者
- ステータス: accepted
- 日付: 2026-09-13

## 問題

Phase 1 にはレビューのパスが存在しない。

そのため Claude に差分をレビューさせると、セッションごとに基準を発明することになる。何を Important とし何を nit とするかの線引きも、どこまで指摘すべきかの上限も、リポジトリのどこにも書かれていない。同じ差分を二度レビューさせると違う結果が返る。

これは人間のレビュアーにとっても同じ問題である。このリポジトリの肝は「変更が成果物の連鎖に辿れること」だが、その適合を誰がどう確かめるかが決まっていない。

加えて、実装を書いたセッションがそのまま自分の差分をレビューしている。書いた本人が承認しているのと変わらない。

## 期待する成果

レビューの基準がリポジトリの中にあり、人にもエージェントにも同じものが適用される。レビューが再現し、その結果がコミットの連なりと同じように監査証跡になる。

差分を書いたセッション以外がレビューを行う経路ができる。

## 影響を受ける利用者とシステム

このリポジトリでレビューを行う人、Claude Code のセッション、将来の PR ワークフロー。

## 制約

- レビュー基準はリポジトリの中に置くこと。セッションの記憶やプロンプトの書き方に依存させない。
- 助言的な制御と決定的な制御を混同しないこと。どちらであるかを、その制御自身に書く。

## 未解決の問い

- 所見を無視できる状態のまま verifier を置くことに意味があるか。真のゲート（ブランチ保護と CODEOWNERS）が無い間、verifier は助言でしかない。
